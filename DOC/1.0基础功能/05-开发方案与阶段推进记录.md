## 3. 各阶段实际推进明细

### 阶段 0:环境搭建(已完成,开工前)

- **任务**:JDK 17(Temurin)、Android Studio 2026.1.4.7、Android SDK(platform 36)、Gradle 8.14、AVD `anythingllm_api36`、项目骨架、首次构建。
- **结果**:debug APK 可安装运行;镜像源配置(Jenkins:JDK 清华 / SDK+Gradle 腾讯 / Maven 阿里云);API Key 入 `.gitignore`。

### 阶段 1:配置与 API 层(2026-09-10)

- **任务**:设置页(地址/Key 掩码/测试连接/高级参数折叠)、ConfigRepository(DataStore + Keystore 加密)、Retrofit 客户端(13 端点)、探活三级(ping→auth)、工作区/文件夹列表、单测。
- **验收**:模拟器内 `http://10.0.2.2:3001` + API Key → "连接正常";列出 7 工作区 + custom-documents;停服/错 Key 中文提示正确。
- **偏离**:加密方案采用 **Keystore 自实现**(避免引入已废弃的 security-crypto 依赖),非 EncryptedSharedPreferences;明文 HTTP 采用全局 `usesCleartextTraffic`(简单方案,审阅时已确认)。

### 阶段 2:选文件与预校验(2026-09-10)

- **任务**:SAF 多选(ACTION_OPEN_DOCUMENT)、预校验器(白名单/大小/空文件)、`ConvertToStorageName` Kotlin 移植(unicode/strip/keep)、校验结果页。
- **验收**:白名单外/超 100MB/空文件正确拒绝并注明原因;中文名转换与 PC 版逐项一致。
- **要点**:存储名转换保留 0x20–0x7E 可打印 ASCII,其余 `u`+4 位小写 hex;emoji 按 UTF-16 代理对处理。

### 阶段 3:批量导入主流程(2026-09-10)

- **任务**:目标选择页(统一/逐项)、上传队列(并发 2)、multipart 构造(metadata 在 file 前)、指数退避重试(2 次)、update-embeddings 触发、docpath 轮询验证(2s→5s,300s 超时)、重复检测四动作 + 应用到全部、替换实现、进度页(暂停/取消)。
- **验收门**:
  - ① 3 文件(含中文)统一模式 → 上传/嵌入/验证全通过,PC 端 sourceDocument 显示中文;
  - ② 重复四动作 + 应用到全部行为正确,替换无孤儿文档;
  - ③ 断网 5.7s → 自动退避重试 → 恢复后成功,"上传重试 2/3"可见。
- **强化测试**(用户要求):用例 A–G 全过(详见 04 文档 §5)。
- **过程中修复的缺陷**:metadata JSON 字符串契约、重复对话框竞态、测试基建两处(详见 06 文档 BUG-001~004)。

### 阶段 4:结果与日志(2026-09-10)

- **任务**:结果汇总页(成功/失败/跳过 + 单条/全部重试)、ImportEngine.retryItems(仅 FAILED 可重试,重置 PENDING 重跑完整管线)、ImportLogRepository(纯 File,JVM 可测)、LogsScreen(倒序/SAF 导出/清理/清空)。
- **验收**:混合结果(2 成功 1 失败)重试流转正确;日志行结构与 PC 版可对照、导出可读、30 天清理与清空生效。
- **单测**:ImportEngineRetryTest(5)+ ImportLogTest(8),总计 66→79 全绿。

### 阶段 5:打磨与交付(2026-09-10)

- **任务**:
  - FR-15 深色模式:`ThemeMode{SYSTEM/LIGHT/DARK}` + ConfigRepository 持久化 + MainActivity 唯一全局主题包裹 + 7 Screen 移除内部 wrapper + 设置页"外观→主题模式"三选;
  - FR-16 服务器状态卡片(Home 已有,回归确认);
  - Release 签名:`keytool` 生成 keystore + build.gradle.kts 自动签名 + `assembleRelease` + `apksigner verify`;
  - 回归 R1–R10(模拟器端到端:连接/单文件导入/预校验/目标选择/统一模式/日志/深色)。
- **验收**:深色↔跟随系统双向切换截图确认;Release APK 7.8MB 签名有效;单测 79 全绿。
- **过程中的编辑事故**:TargetScreen 编码事故(GBK mojibake)等 7 项,全部修复(详见 06 文档 BUG-006~012)。

## 4. 与原计划的偏离汇总

| # | 计划项 | 实际 | 原因/说明 |
|---|---|---|---|
| 1 | FR-13 日志 P1 | 升为 **P0** | 审阅意见:结果可追溯是核心诉求 |
| 2 | EncryptedSharedPreferences | Keystore 自实现加密 | security-crypto 已废弃;自定义 KeyStoreCrypto 更稳 |
| 3 | networkSecurityConfig 放行域名 | 全局 usesCleartextTraffic | 审阅时确认取简单方案,HTTPS 后续收紧 |

| 6 | 真机回归 R11 | 未执行,模拟器交付 | 用户未提供真机;验收时明确"模拟器交付为底线" |
| 7 | 前台 Service 防杀 | 未实现 | 计划风险项,未触发(模拟器场景);列为后续建议 |

## 5. 阶段门管理经验(供后续项目复用)

1. **门必须可验证**:每个验收门都落到可执行动作(点某按钮/看某提示/查服务器文件),避免"看起来能跑"。
2. **服务器侧核验不可省**:上传成功必须回查服务器 storage / 工作区详情,不能只看 App 端 success。
3. **强化测试前置**:阶段 3 完成即做混战测试(大文件+emoji+重复+逐项路由),提前暴露竞态与超时问题。
4. **文档随验收更新**:每次验收结束立即追加到 03 文档,避免事后回忆失真。
5. **源码编辑红线**:Kotlin 文件禁止 PowerShell Set-Content(GBK 编码事故),见 06 文档 BUG-006 教训。
