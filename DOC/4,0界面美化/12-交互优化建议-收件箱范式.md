# 12 · 交互优化建议：从"管理工具"转向"收件箱范式"

> 阶段：4.0 界面美化 · 版本基线 v1.5.0 / v1.6.0
> 日期：2026-09-14
> 核心判断：**当前 UI 不缺功能，缺的是"收进来就好"的默认行为。** 三个平级概念 Tab、三条并行入库路径、"先勾选再弹窗"的整理方式，把一个高频收集工具做成了低频管理后台。建议参照 Cubox / flomo / 抖音收藏的收件箱范式重构核心链路。

---

## 一、结论先行

| | 现状 | 目标 |
|---|---|---|
| 心智模型 | 三个概念：收集箱 / 知识库 / 资料库 | **一个收件箱 + 一个"库"** |
| 接收分享 | 接收后直接跳进 App 主界面 | 轻量反馈"已收到 N 项"，不打断分享方 |
| 单条整理 | 勾选 → 点按钮 → 弹窗选文件夹 → 弹窗选工作区 → 确认（5 步 2 弹窗） | **左滑/右滑即分类**，零决策 |
| 默认行为 | 无默认入库位置，每次都要选 | 设一次"默认文件夹+工作区"，之后一键入箱 |
| 入库路径 | 标记 / 即时导入向导 / 资料库 FTP 三条并行 | 统一为"收件箱 → 一键入箱 → 点同步" |

**一句话：让用户在分享时只需"点分享 → 选本 App"，剩下的分类、选库、校验都用默认值替他做完。**

## 二、当前操作链路为什么繁琐（代码级诊断）

### 2.1 三条入库路径并存，概念重叠

| 路径 | 入口 | 后续 | 落地代码 |
|---|---|---|---|
| A. 标记入库 | 收集箱勾选 →"标记"→ 选文件夹+工作区 | Tab2 知识库"已标记计划"→ 点"连接服务器并同步"走 AnythingLLM 嵌入 | `CollectScreen.kt` MarkDialog → `KnowledgeScreen.kt` onSync |
| B. 即时导入 | 主页"即时导入" | 选文件 → 校验 → 选目标库 → 进度，4 步向导 | `AppNav.kt` SELECT→VALIDATE→TARGET→IMPORT |
| C. 资料库 FTP | 收集箱勾选 →"归入资料库" | Tab3 资料库文件夹树 →"同步到 PC"走 FTP | `CollectScreen.kt` ArchiveDialog → `LibraryScreen.kt` onSyncFtp |

用户必须搞懂：**"标记"和"归入资料库"有什么区别？什么时候走服务器嵌入、什么时候走 FTP？知识库和资料库是一回事吗？** 这三个 Tab 的命名（`HomeScreen.kt:96-113` 的 NavigationBar）没有给出答案。

### 2.2 单条整理的真实点击成本

以整理**一条**链接为例（`CollectScreen.kt`）：

1. 点条目左侧 `Checkbox`（`EntryRow:204`）
2. 点底部"标记 N 条"按钮（`CollectScreen.kt:128`）
3. 在 `MarkDialog` 里从 Radio 列表选文件夹（`:268`）
4. 再从另一个 Radio 列表选工作区（`:279`）
5. 点"标记"确认（`:290`）

**5 次点击 + 2 个居中弹窗**，且第 1 步必须先勾选——哪怕只整理一条也要走"多选模式"。对标：抖音收藏是**点一下就进默认夹**，长按才选夹。

### 2.3 接收链路打断分享方

`ShareReceiver.kt:110` `openCollector()` 接收完直接 `startActivity(MainActivity)` 并 `CLEAR_TOP`——用户在微信/浏览器点分享后，会被硬生生拽进本 App 主界面，分享流程被打断。没有"静默收进收件箱"的选项。

### 2.4 设置页没有"默认值"

`SettingsScreen.kt` 只有连接参数（服务器/API Key/FTP）和高级参数（超时/并发/文件名策略），**没有"默认入库文件夹 / 默认工作区"**。这意味着每次分类都要重新选，没有任何记忆。

## 三、标杆范式调研（网页查证）

| 产品 | 可借鉴的核心做法 | 来源 |
|---|---|---|
| **Cubox** | 分享菜单一键保存；自动解析正文；"**不整理也能井井有条**"——智能列表按规则自动归类；收藏即完成，分类后置 | help.cubox.pro/hi/5bca、6.0 更新日志 |
| **flomo 浮墨** | 输入框即主界面，**无需选分类、无需起标题**，"像发微信一样"；用标签而非文件夹，避免决策瘫痪 | flomoapp.com、什么值得买对比测评 |
| **抖音收藏** | 单击**默认收藏进默认夹**，长按才弹收藏夹——零决策默认 + 长按进阶 | CSDN 收藏模块设计分析 |
| **Save On Your Phone** | **左滑归档、右滑打标签**，滑到底删除带确认；保存时**短震动**确认，走路时不用看屏幕；inbox triage 收件箱分拣 | savesync.org/mobile-quickstart |
| **Linkding** | 重要操作（+）固定在**底部中央拇指区**；触摸目标 ≥44dp；移动端操作成功率 68%→92% | CSDN Linkding UX 分析 |

**五条范式的共同规律：**
1. **先进来，别问**——接收时零决策，分类后置或自动。
2. **一个默认值走天下**——大多数条目 80% 情况进同一个地方。
3. **手势分拣 > 勾选弹窗**——滑动比"勾选→点按钮→弹窗"快一个数量级。
4. **拇指区操作**——常用动作放底部，别藏在居中 AlertDialog 里。
5. **接收要有"已收到"的非视觉反馈**——震动比跳页友好。

## 四、优化建议（按优先级）

### P0 · 改动小、收益大，本轮即可做

#### P0-1 增加"默认入库位置"，一键入箱
- **问题**：每次分类都要手选文件夹+工作区（2.2 节）。
- **建议**：设置页新增"默认文件夹 / 默认工作区"（可留空=只同步不嵌入）。收集箱顶部加一条主操作：**"全部入默认箱（N 项）"**，条目本身也可点"入默认"。对标抖音默认收藏夹。
- **落点**：`SettingsScreen.kt` 加两个下拉；`CollectScreen.kt` 顶部加主按钮；`CollectRepository`/`ConfigRepository` 持久化两个字段。
- **收益**：80% 的条目从 5 步降到 1 步。

#### P0-2 接收不跳页，改为轻量确认
- **问题**：`ShareReceiver.openCollector()` 硬跳主界面，打断分享方（2.3 节）。
- **建议**：接收后只发一条系统/应用通知"已收集 N 项，待整理"，并触发一次短震动；**不强制拉起 MainActivity**。用户想整理时自己点开。
- **落点**：`ShareReceiver.kt:110` `openCollector()` 改为可配置行为（默认静默）；加 `Vibrator` 短脉冲。
- **收益**：分享场景从"被打断"变"无感收集"，这是收藏类产品的立身之本。

#### P0-3 条目手势分拣替代"勾选+弹窗"
- **问题**：整理单条要先勾选再弹两个居中对话框（2.2 节）。
- **建议**：`EntryRow` 加滑动：
  - **左滑** → 入默认箱（P0-1 的默认值）
  - **右滑** → 标记到"上次使用的文件夹+工作区"（记住上次选择）
  - **滑到底** → 删除（带撤销 Snackbar）
  - **长按** → 进入多选模式（现有批量能力保留）
  - **单击** → 底部 `ModalBottomSheet` 快速分类（替换居中 `AlertDialog`，拇指可达，可"连续整理下一条"）。
- **落点**：`CollectScreen.kt` 的 `EntryRow`；Compose 用 `SwipeToDismiss` 或 `Modifier.draggable` 自绘背景色条。
- **收益**：单条整理从 5 步变 1 个滑动手势。

#### P0-4 整理面板从中居弹窗改底部抽屉
- **问题**：`MarkDialog`/`ArchiveDialog` 是 `AlertDialog`，文件夹 Radio 列表超过一屏（代码注释 `:267` 自己都写了"目录多时对话框超高"）。
- **建议**：统一改成 `ModalBottomSheet`：顶部显示当前条目标题，下面是横向文件夹胶囊（常用文件夹置顶）+ 工作区下拉，底部"入箱并看下一条"。
- **收益**：拇指区可达，且支持连续分拣（inbox zero 工作流）。

---

### P1 · 重塑信息架构，中期做

#### P1-1 三个 Tab 收敛为"收件箱 + 库"
- **问题**：收集箱/知识库/资料库三个平级概念让用户困惑（2.1 节）。
- **建议**：
  - **首页 = 收件箱**（现收集箱），这是用户 90% 时间待的地方。
  - **第二个 Tab = "库"**：合并现"知识库"与"资料库"——一个统一列表，每条用徽标标来源（☁ 服务器嵌入 / 📁 本地+FTP），顶部一个主按钮"同步"自动分流：能走服务器的走服务器，离线的走 FTP。
  - 设置/日志收进右上角图标，不再占 Tab。
- **收益**：从"要理解三个概念"变成"一个收件箱 + 一个库"。

#### P1-2 即时导入向导 4 步压成 2 步
- **问题**：主页"即时导入"走 SELECT→VALIDATE→TARGET→IMPORT 四页（`AppNav.kt`），且每次都要重选目标库。
- **建议**：记住"上次目标库"；选完文件（`SelectScreen`）后**后台自动校验**，直接进"导入确认页"（预填上次目标库，可改），去掉独立的 ValidationScreen。
- **收益**：重复导入同库文件时，选完文件即开始。

#### P1-3 智能默认/自动归类
- **问题**：链接全靠人脑判断进哪个文件夹。
- **建议**：参照 Cubox 智能列表，支持简单规则——"来自某域名（如 zhihu.com / mp.weixin）自动进某文件夹""PDF 自动进'论文'夹"。规则在设置里一次配好。
- **收益**：高频来源接近零整理。

---

### P2 · 锦上添花

- **P2-1 首启强引导**：现在首启只有 `HomeScreen.kt:173` 的三步文字对话框。改成"填服务器地址 → 测试连接 → 成功后引导分享一条链接进来"的真实走查。
- **P2-2 液态 Tab 指示器**：见上一份动效评估，唯一强适配项，给新"收件箱/库"双 Tab 用 spring 流动。
- **P2-3 列表重排回弹**：条目入箱/删除后用 `animateItemPlacement(spring)`，让"分拣"有物理反馈。

## 五、前后对比：一次"整理 5 条链接"的操作路径

| | 现状 | 优化后 |
|---|---|---|
| 分享到本 App | 被拉进主界面，看到列表 | 震动+通知"已收到 5 项"，App 可不开 |
| 整理第 1 条 | 勾选 → 标记 → 选文件夹 → 选工作区 → 确认 | **左滑**（进默认箱），或右滑进上次夹 |
| 整理第 5 条 | 重复上面 5 步 | 连续滑 5 下，完 |
| 决定进哪个库 | 记住"标记=服务器、归档=FTP" | 不用管，统一"入箱"，同步时自动分流 |
| 触发同步 | 切到知识库 Tab → 点大按钮 | 收件箱顶部"同步 N 项" |

**点击次数：从 25 次（5 条×5 步）降到 5 次滑动手势。**

## 六、落地建议顺序

1. **本轮（4.0 收尾）**：P0-1 默认箱 + P0-2 接收静默 + P0-3 手势分拣 + P0-4 底部抽屉。纯 Compose 改动，不动数据模型主结构，可附带单测。
2. **下一个小版本**：P1-1 双 Tab 收敛 + P1-2 向导瘦身。涉及导航重组，需回归现有 163 个单测与 uiautomator 用例。
3. **再往后**：P1-3 自动规则 + P2 体验项。
