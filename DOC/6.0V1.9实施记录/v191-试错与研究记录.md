## 1. To 拖拽"从上往下不生效"根因定位(重要)

### 现象
- 从下往上拖(第 2 行拖到第 1 行):正常,`favorites.json` sortOrder 变更。
- 从上往下拖(第 1 行拖到第 2 行):无效果,`favorites.json` 不变。

### 排查过程
1. **加长拖拽距离无效**:拖 332px(工作 y588→920)依然无效果 → 排除"位移阈值/四舍五入不够"。
2. **读 favorites.json 验证**:`adb shell run-as com.anythingllm.importer sh -c 'cat files/favorites/favorites.json'` → sortOrder 未变 → reorder 从未被调用。
3. **结论**:旧实现 `onDragEnd` 里一次性 `(dragOffset/itemSpanPx).roundToInt()` 换算 + 仅 onDragEnd 提交,存在两个缺陷:
   - 拖拽手势结束回调不稳定(方向不对称疑似 SwipeToDismissBox / LazyColumn scrollable 手势仲裁差异),`onDragCancel` 分支只重置不提交 → 顺序丢失;
   - `itemsIndexed` 的 `index` 与 `order` 在 pointerInput 闭包中捕获首次组合快照,列表顺序变化后闭包内是旧值(Compose pointerInput 在 key 不变时不重启)。

### 修复方案(v2,已落地并实测双向通过)
- `previewOrder`(remember State):onDragStart 快照当前顺序;onDrag 实时按 `(dragOffset/itemSpanPx).roundToInt()` 交换预览并**归零 offset**(以新位置为基准继续累积);
- `onDragEnd` 与 `onDragCancel` **都**调用 `commitPreview()`(与 orderRef 不同才落库) → 取消不再丢序;
- `orderRef = remember { mutableStateOf(order) }` + `LaunchedEffect(order) { orderRef = order }`:pointerInput 闭包始终读 State 最新值,避免快照过期;
- 渲染顺序 `displayFolders` 拖拽中取 previewOrder,否则 orderRef;
- 局部函数 `commitPreview()` 必须在引用它的闭包**之前**声明(Kotlin 局部函数不支持前向引用,编译报 Unresolved reference)。

### 验证方法(可复现)
- 从上往下:DOWN(400,590) → 900ms → MOVE(400,660/710/760) → UP → favorites.json: 积累0/工作1 ✓
- 从下往上:DOWN(400,745) → 900ms → MOVE(400,660/580/510) → UP → favorites.json: 工作0/积累1 ✓
- 采样坐标基于 1080x2400:第 1 行卡中心 ~590px,第 2 行 ~745px;长按 900ms 确保 detectDragGesturesAfterLongPress 触发。

## 2. Sync 页卡死根因定位(三处,均已修)

### 根因 A:空批次/无待同步条目时 running 永不复位
`SyncViewModel.onEngineState` 旧逻辑要求 `st.isTerminal`(items 非空且全终态)才复位;引擎对空批次立即结束但 isTerminal 恒 false → running 保持 true → 按钮禁用 + "同步中" 卡死。
**修复**:`onEngineState` 改为 `if (!st.running)` 即复位(refreshFolders + 清 running + finished 提示);`runSync` 整体 try/catch 兜底。

### 根因 B:FTP 未配置时 markAllFailed 不改 running
`CollectFtpSyncEngine.launch` 未配置分支只 `markAllFailed(...)` 后 return,`running` 保持 true → 页面永久"同步中 1/1"。
**修复**:markAllFailed 后补 `_state.update { it.copy(running = false) }`。
> 这是实测中最先撞到的卡死场景,截图证据 `v191_sync_ftp_err.png`(同步中 1/1 卡住)。

### 根因 C(潜在):LLM 引擎异常路径
`runSync` 协程异常时 finally 复位 running;补了 try/catch 后异常也会给出 error 文案并复位,杜绝状态流异常卡页面。

### 验证方法
- FTP 未配置:切 FTP Tab → 一键同步 → 6 秒后应显示"有 1 项同步失败,可重试"+ 按钮恢复(旧版卡"同步中 1/1");
- 空批次:LLM 同步成功后所有条目 DONE → 一键同步 → "暂无待同步条目"+ 按钮可用;
- 真同步:LLM Tab → 一键同步 → 积累"已同步"(服务器端文件落盘 + workspace 回写)。

## 3. Mark 卡片三色体系实现细节

- 语义色(固定不可自定义):未归入绿 `0xFF16A34A`、回收站红 `0xFFDC2626`;已归入 = 收藏夹自定义色(folderColor,缺失回退灰 `0xFF64748B`);
- 卡片背景 `cardColor.copy(alpha=0.24f)` + 边框 2dp 同色;**初版 0.13 实测过淡**(像素采样与背景白差异仅 30-50),调到 0.24 后区分明显;
- 回收站标题 `textDecoration = LineThrough`(仅回收站);
- 像素验证:绿(177,211,195)/橙(231,210,180)/红(212,172,177);删除线检测 = 标题中间高度存在整行横穿暗线(y1344-1345, 323px)。
- 注意:Mark 卡片与收藏夹配色联动需 `folderColor` 参数链路(MarkEntryCard/SwipeableMarkRow),新增字段时要同步传参,漏传会回退灰色。

## 4. 多设备 adb 问题(会话期间新出现)

- 现象:`adb devices` 出现两个设备:`8BRX1EA7Z`(真机,来源未确认,本次会话期间出现)+ `emulator-5554`(AVD anythingllm_api36);
- 影响:所有 `adb shell / install / exec-out` 报 `more than one device/emulator`,screencap 产生空文件;
- 处理:一律 `-s emulator-5554` 指定;**未对真机做任何安装/卸载/写入操作**(避免干扰用户设备);
- 后续:v1.9 遗留"真机手势复核"待办可考虑用真机执行(需用户确认该设备归属)。

## 5. 其他记录

- **PowerShell 5.x 不支持 `&&`**,串命令用 `;`;cmd /c 重定向 screencap 避免 PowerShell 编码污染 PNG。
- **git 提交**固定流程:UTF-8 无 BOM 写 `.gitcommitmsg.txt` → `git add -A; git commit -F .gitcommitmsg.txt` → `git rm --cached .gitcommitmsg.txt; Remove-Item` → 清理提交。
- **Kotlin 局部函数前向引用**:编译报 `Unresolved reference`,声明需在使用之前。
- **Compose pointerInput 闭包捕获**:key 不变时闭包保留首次组合快照,普通 val(如 order)会过期,须用 mutableStateOf + LaunchedEffect 同步。
