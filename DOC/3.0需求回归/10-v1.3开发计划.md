## 1. 需求整理(用户原始表述 → 整理结论)

### 1.1 用户表述

> 1.3版本开发,未安装AnythingLLM知识库的用户……全面测试一下,当用户未安装 AnythingLLM 数据库的时候的全程操作。目前是否有这个功能,若没有,则先设计,再冒烟测试,再执行。
> 手机端设计要点:在手机端建立资料库文件夹,包括文件目录的管理。
> PC端设计开启FTP的服务脚本,采取FTP的方式同步文件。

### 1.2 现状结论(已核实)

| 检查项 | 结论 |
|---|---|
| v1.0 即时导入 | 依赖 AnythingLLM 服务器(3001),无服务器 → 连接失败提示 |
| v1.2 同步模式 | 名义上"同步软件",**仍依赖运行中的 AnythingLLM 服务器**(纯上传到 `document/upload/{folder}`,C-01 拍板:载体=服务器 documents 目录) |
| 无服务器时的表现 | `refreshSnapshot`/`syncNow` 均报"连接服务器失败:…",App 无任何可用的降级同步通道 |
| 资料库/文件目录管理 | 全仓库 grep 无 `ftp`/`资料库`/`library` 业务代码(仅 UI 图标 LibraryBooks 误命中) |
| **结论** | **该功能不存在,需从设计开始全新开发** |

### 1.3 需求三(用户原始需求回归)→ v1.3 整理结论

| 项 | 结论 |
|---|---|
| 核心痛点 | 未安装 AnythingLLM 的用户也想用本 App 管理/归档手机资料,并同步到 PC 目录;当前无任何可用链路 |
| 手机端 | 建立**资料库**(本地目录树),提供**文件目录管理**:文件夹的新建/重命名/删除、条目的归档(从收集箱移入)/移动(改目标文件夹)/删除/查看;不依赖服务器,永远可用 |
| PC 端 | 提供**开启 FTP 服务的脚本**(无需 AnythingLLM),脚本启动后 PC 暴露一个可写目录 |
| 同步方式 | 手机 App 作为 **FTP 客户端**,主动把资料库内容按文件夹结构**上传同步**到 PC(增量:仅上传未同步/已变更条目) |
| 与 v1.2 关系 | v1.2 收集箱/快照/标记/一键同步(依赖服务器)全部保留;v1.3 新增**独立第三通道**(资料库 + FTP),两者并存互不干扰 |
| 边界 | v1.3 只做"手机 → PC"的单向上传同步;不做双向/下载(避免手机端删文件风险);链接条目以 `.url` 文本形式落盘 PC |

## 2. 总体设计

```mermaid
flowchart LR
    subgraph 手机端 App
        C[收集箱<br/>v1.2 保留] -->|勾选·归档| L[资料库 Library<br/>目录树 + 条目]
        L -->|文件目录管理<br/>新建/重命名/删除/移动| L
        L -->|FTP 上传同步| F
        S[设置页<br/>FTP 配置] --> F
    end
    subgraph PC 端(无 AnythingLLM)
        P[ftp_server.py<br/>pyftpdlib FTP 服务<br/>根目录=PC 同步目录] --> D[(PC 目录<br/>镜像资料库文件夹树)]
    end
    F[FtpSyncEngine<br/>FTP 客户端] -.局域网 FTP.-> P
```

- **双通道并存**:依赖服务器的 v1.2 链路(收集箱→标记→一键同步)原样保留;v1.3 新增资料库 + FTP 链路,未配置/无法连接服务器时 App 仍完整可用。
- **资料库与收集箱的关系**:收集箱是"待整理暂存区",资料库是"归档后的正式目录树"。归档 = 移动(文件副本从 collect 移到 library,收集箱条目删除,资料库建条目),不重复占空间。

## 3. 手机端设计

### 3.1 数据模型(`data/library/LibraryModels.kt`)

```kotlin
@Serializable data class LibraryFolder(
    val id: String,          // UUID
    val name: String,        // 文件夹名(展示层去重;存储不强制唯一)
    val parentId: String?,   // null = 根级
    val createdAt: String,   // ISO-8601
)

@Serializable enum class LibraryEntryType { FILE, LINK }

@Serializable data class LibraryEntry(
    val id: String,
    val type: LibraryEntryType,
    val folderId: String?,       // null = 根级
    val title: String,           // FILE=文件名;LINK=标题(缺省=域名)
    val url: String? = null,     // LINK 专用
    val localPath: String? = null, // FILE 副本绝对路径
    val sizeBytes: Long = 0,
    val addedAt: String,
    val syncedAt: String? = null, // FTP 同步时间;null=未同步
    val syncedPath: String? = null, // 远端相对路径(增量依据之一)
    val syncedSize: Long = -1,    // 同步时文件大小;不一致视为已变更需重传
)
```

- 存储:`library/library.json`(folders + entries 整体序列化,kotlinx,风格对齐 CollectRepository);文件副本 `library/files/{entryId}_{name}`。
- **移动 = 元数据变更**(改 folderId),不实际搬文件,简单可靠;同步时按 folderId 反查路径。
- 删除文件夹策略:删除文件夹时其**直接子条目移到根级**,子文件夹级联递归同规则(不物理删文件,防误删数据);文件删除才物理删除副本。

### 3.2 仓储(`data/library/LibraryRepository.kt`)

纯 java.io.File 实现,不依赖 Context(JVM 可单测),对外提供:

| 方法 | 说明 |
|---|---|
| `folders() / entries()` | 全量读(损坏容错,空数据返回空) |
| `createFolder(name, parentId)` | 新建(同级重名自动追加序号) |
| `renameFolder(id, newName)` | 重命名 |
| `deleteFolder(id)` | 级联:子文件夹上移父级,子条目上移父级 |
| `childrenOf(folderId)` | 子文件夹 + 条目(排序:文件夹在前,按名) |
| `pathOf(folderId)` | 根→该文件夹的名称链(FTP 目录映射用) |
| `archiveFromCollect(entry, destFolderId)` | 收集箱 → 资料库:移动文件副本,建 LibraryEntry,返回新条目 |
| `moveEntry(id, folderId)` | 条目改目标文件夹 |
| `deleteEntry(id)` | 删元数据 + 物理删副本 |
| `pendingSync()` | 待同步条目:syncedAt==null 或 syncedSize!=当前大小 |

### 3.3 FTP 配置(ConfigRepository 扩展)

DataStore 新增键(非敏感,明文存储):

| 键 | 默认 | 说明 |
|---|---|---|
| `ftp_host` | "" | FTP 服务器地址(PC 局域网 IP) |
| `ftp_port` | 2121 | 端口(与 PC 脚本默认一致) |
| `ftp_user` | "sync" | 用户名(与 PC 脚本默认一致) |
| `ftp_password` | "sync123" | 密码(与 PC 脚本默认一致) |
| `ftp_remote_root` | "Library" | 远端根目录名(PC 同步目录下建该子目录) |

`AppConfig` 增加 `FtpConfig` 字段;设置页新增"FTP 同步"分区(主机/端口/账号/密码/远端根 + 测试连接)。

### 3.4 FTP 同步引擎(`domain/ftp/FtpSyncEngine.kt`)

- **客户端**:Apache Commons Net `FTPClient`(commons-net:3.11.1,纯 Java、Android 兼容、无新权限)。
- **连接**:被动模式 `enterLocalPassiveMode()`,超时 10s,登录后 `setFileType(BINARY)`。
- **目录规划**:遍历资料库文件夹树,远端路径 = `{remoteRoot}/{name链...}`;逐级 `makeDirectory`(已存在忽略 550)。
- **文件条目**:上传本地副本;完成回写 `syncedAt/syncedPath/syncedSize`。
- **链接条目**:生成 `{title清洗}.url` 文本(`[InternetShortcut]\nURL={url}`)临时文件上传,回写同步状态。
- **增量**:仅 `pendingSync()` 条目;上传失败保留未同步状态,可重试;带重试(2 次,2s 起指数退避,与 v1.0 口径一致)。
- **并发**:并发 1(串行,简单可靠;FTP 会话状态敏感,不做多连接)。
- **安全**:文件名清洗(去除 `/\:*?"<>|` 与控制字符),防路径穿越。
- **命名(实现定稿,与 v1.0 上传命名区分)**:FTP 同步到 PC 目录属"用户个人文件",采用 **UTF-8 可读名**(保留中文,仅清洗非法字符),而非 AnythingLLM 上传用的 uXXXX ASCII 化——PC 端目录直接可见、可双击打开,可读性优先;两端控制编码均设 UTF-8(commons-net `setControlEncoding("UTF-8")` + pyftpdlib `handler.encoding="utf-8"`),中文文件名实测正常。
- 引擎输出 `FtpSyncState{running, items:[{title,status,message}], done/total}`,UI 展示进度。

## 4. PC 端设计:开启 FTP 服务的脚本

### 4.1 技术选型

| 候选 | 结论 |
|---|---|
| Windows IIS FTP | 需管理员+启用功能,重 |
| WSL vsftpd | 依赖 WSL 发行版安装,侵入大 |
| **Python pyftpdlib** | **选型**:单文件脚本、免管理员、跨平台、本机已有 Python 3.14.7;`pip install pyftpdlib` 一次完成 |

### 4.2 交付物(tools/ftp-server/)

| 文件 | 说明 |
|---|---|
| `ftp_server.py` | FTP 服务脚本(pyftpdlib):参数化根目录/端口/账号/密码;启动打印本机局域网 IP 与连接信息;Ctrl+C 停止 |
| `start-ftp-server.bat` | 启动器(纯 ASCII 内容防 GBK 乱码):检测 pyftpdlib → 缺失提示安装命令 → 运行脚本 |
| `README.md` | 使用说明:安装/启动/手机端配置步骤/防火墙放行提示 |

### 4.3 脚本参数与默认值

```
python ftp_server.py [--root D:\AnySync] [--port 2121] [--user sync] [--password sync123]
默认:root=脚本同级 any-sync 目录(自动创建);port=2121;user=sync;password=sync123
```

- 启动后自动列出本机全部 IPv4 地址(提示手机填哪个)。
- 日志:连接/登录/上传/断开,时间戳输出到控制台。
- 密码支持明文参数与 `--password-env`(取环境变量,避免命令行泄露);默认密码在 README 提示首次使用后修改。

## 5. 同步协议与增量策略

| 项 | 约定 |
|---|---|
| 传输 | FTP 主动上传(手机→PC),被动模式,二进制 |
| 远端目录 | `{remote_root}/{文件夹名链...}/{条目文件名}` |
| 链接落盘 | `{title}.url`,内容 `[InternetShortcut]\nURL={url}`(PC 双击可打开) |
| 增量判定 | 未同步(`syncedAt==null`)或 `syncedSize != 当前文件大小` → 重传;已同步且未变 → 跳过 |
| 失败处理 | 单条目失败保留待同步,汇总展示,可整批重试;服务端目录已存在同名 → 覆盖上传(幂等) |
| 幂等性 | 同名同大小文件重复同步直接覆盖,不报错 |
