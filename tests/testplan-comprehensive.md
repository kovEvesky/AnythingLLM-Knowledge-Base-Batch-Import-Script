## 一、测试目标



1. 验证 V0.1–V0.7 全部功能在 **Windows 端 + AnythingLLM (WSL) 全链路**下正确工作；

2. 重点回归本次修复：**非交互模式（重定向输入）下交互菜单不再卡死**（Read-Host / 确认 / 重复处理）；

## 二、负载控制设计（v1.1 新增，针对本机配置）

本机 LLM 为 Ollama 本地模型 `qwen2.5:14b-instruct`（约 8.37GB），推理慢、冷启动约 60–90s。为避免测试被大模型推理拖垮，脚本做以下设计：



| 控制项               | 设计                                                         | 效果                          |
| ----------------- | ---------------------------------------------------------- | --------------------------- |
| **LLM chat 默认关闭** | E5 检索用例默认 `SKIP`，仅 `-RunHeavyChat` 开关执行                    | 默认测试**零** 14B 推理            |
| **嵌入调用合并**        | Setup 阶段一次多文件上传（6 文件）；G1/H1/I 类复用同一次运行输出；H3 改为 1 嵌入 + 2 轻量 | 全流程嵌入约 **4–5 次**（原方案约 12 次） |
| **可选预热**          | `-Warmup` 开关：测试前先跑一次最小 query，冷启动时间从用例时长中剥离                 | 用例耗时更真实                     |
| **单用例硬超时**        | 嵌入 240s /chat 300s / 轻量 30–90s，超时即 Kill 并标记 FAIL/SKIP      | 不会无限挂起                      |
| **报告含耗时**         | 每用例耗时 + 总耗时写入报告                                            | 可评估负载                       |

**预计默认总时长**（不开 chat、不预热）：约 **3–8 分钟**（取决于 Ollama 嵌入模型加载与 AnythingLLM 嵌入吞吐）。`-Warmup` 另加约 60–90s。

## 三、冒烟测试（先行轻量验证，全面测试前必跑）

**设计原则**：任何全面测试执行前，先用最轻量方式确认核心链路正常 —— 冒烟不过直接中止，不浪费全面测试时间。



| 步骤 | 检查项              | 方式                                                   | 负载      |
| -- | ---------------- | ---------------------------------------------------- | ------- |
| S1 | AnythingLLM 服务可达 | `GET /api/ping`                                      | 极轻      |
| S2 | API Key 鉴权有效     | `GET /api/auth`                                      | 极轻      |
| S3 | 目标工作区存在          | `GET /api/v1/workspaces`                             | 极轻      |
| S4 | 最小上传 + 嵌入        | 最小文件 `t_smoke.txt` + `-WorkspaceSlug -NoPause` 真实跑一次 | 1 次最小嵌入 |
| S5 | 嵌入状态确认           | API 查 `t_smoke.txt` status=completed                 | 极轻      |



* 冒烟测试内置于执行脚本，**任何运行模式（含默认、**`-RunHeavyChat`**）都会先跑**；

* 冒烟失败：输出失败步骤与原因，**退出码 1，中止全面测试**；

* `-SmokeOnly`：只跑冒烟，通过即退出（用于快速确认环境）；

* 冒烟通过后自动清理 `t_smoke.txt`，预计耗时 **30s–2min**（含首次嵌入模型加载）。

## 六、执行与判定规则



1. **断言以退出码 + 文档库 API 状态为主**，不依赖终端中文文本匹配（规避 win-shell ANSI 乱码干扰）；

2. 每个用例独立捕获 stdout/stderr/ 退出码 / 耗时，**硬超时**（嵌入 240s /chat 300s / 轻量 30–90s）；

3. 修改 config.json 的用例（C3/C4/D7）执行前备份、执行后**逐字节恢复并校验**；

4. 测试产生的文档统一 `t_` 前缀，结束默认清理（F1/F2），`-KeepTestDocs` 可保留；

5. 报告输出：控制台逐例 PASS/FAIL/SKIP + `tests/results/report-<时间戳>.txt`（含每例耗时、总耗时、负载开关）。

## 七、验收标准



* **必须全绿**：A 类、B 类、C1–C4、D1–D7、E2/E3/E4、F 类、G1/G3、H 类、I 类

* 允许 SKIP（附原因）：E5（默认跳过，属负载控制设计）

* 任何 FAIL 需附：用例编号、实际退出码、输出摘要、根因猜测

## 八、风险与注意事项



1. **Ollama 冷启动**：默认不触发 14B chat；嵌入模型若首次加载会略慢（已并入用例超时预算）；

2. **服务不可达用例（C3）**：仅临时改 baseUrl 指向本机关闭端口，不动 AnythingLLM 服务本身；

3. **测试文档清理**：仅删除 `t_` 前缀文档，不影响现有 4 份正式文档；

4. 全部用例在 Windows 端执行（embed.ps1 是 Windows 工具），AnythingLLM 服务保持 WSL 运行；

5. 若机器负载过高（CPU / 内存紧张），建议加 `-Warmup` 后重跑，或只跑 `-CaseFilter` 指定关键用例。

### 3. v1.3 优化点（基于研究结论）

1. **D6 断言加强**：由"exit=0 不卡"升级为"重传后工作区 t_dup 数量不增加"（真正验证判重生效）。
2. **新增 W1 用例**：全部清理后校验 3 份正式文档（WSL.md / raw-5-* / test-doc.txt-*）仍在工作区——防止"清理前缀误匹配删掉正式文档"类事故复发（R3 阶段曾发生 Agent 用 test-* 前缀误删 test-doc.txt 关联）。
3. **报告增加系统库残留统计**：统计 custom-documents 中 t_* 残留数，提示环境限制。
4. **报告增加"已知限制与建议"段**：物理删除接口假成功 / 系统库残留无法 API 清理 / chat 需 -RunHeavyChat / 备份目录说明。

### 4. 环境限制（实测确认，非 bug）

- `POST /api/v1/system/remove-documents` 返回 {"success":true} 但文档不物理删除（REST 与 MCP 桥(:3002) 均如此）→ 清理 = update-embeddings deletes 解除关联，系统库文件残留。
- `POST /api/v1/workspace/{slug}/upload` 与 `/delete-documents` 路由不存在（返回 SPA HTML）。
- 工作区文档对象无 title 字段（title 在 metadata JSON 内）——判重等逻辑须基于 filename/docpath。
- PowerShell 5.1 `-File` 下位置参数与命名开关混用会被吞（自动化须 cmd /c 或引号包路径）。

### 5. 建议（供后续迭代）

1. 若需清理系统库残留：在 WSL 中直接管理 AnythingLLM 数据目录（custom-documents），或升级 AnythingLLM 版本修复物理删除接口。
2. 判重语义可选增强：同名但内容变更时提示"替换"（当前仅同名跳过）。
3. 可加入 CI 钩子：每次修改 embed.ps1 后自动跑 `-SmokeOnly`（约 4s）作为快速回归。
4. 备份策略：每次工具修复/测试方案变更后执行 `backup_<时间戳>` 完整备份（含 .git）。
